A sudden server crash is every developer's nightmare, and that's where this one starts. One afternoon the server went down without warning. It ran Nginx as a reverse proxy in front of a PHP Laravel backend, a setup that had been stable until then.

  <Step focus="ec2,cw,sns" show="cw,sns">

  <Step panel="after" focus="alb,app1,app2" show="aws,vpc,public,app,asg,alb,app1,app2">
    The attack showed how fragile a single monolithic instance was. The app also served a mobile client over websockets. Rather than a big refactor, I decoupled only what was needed to make the server **stateless**, so instances could come and go behind a **load balancer**.
  </Step>

  <Step focus="rds,s3,app2" show="data,rds,s3,users">
    Making it stateless meant moving state out. The MySQL database went to **Amazon RDS**. User images and other static files went to **S3**. Now any instance could serve any request.
  </Step>

  </Step>

## Terraform, on purpose

A two-tier upgrade would have been the straightforward option. I saw the incident as a chance to learn **infrastructure as code** properly, even on a freelance project. Being able to deploy and destroy the whole environment on demand keeps it clean and reviewable.

The state lives in an **S3 backend**, so it's stored remotely and consistently for anyone working on it. I validated the setup by deploying the foundations first: VPC, subnets and security groups.

I also added **Checkov** to scan the plan for security and compliance misconfigurations before anything reached AWS:

```bash
python3 -m venv .env
source .env/bin/activate
pip3 install checkov
```

```bash
#!/bin/bash
terraform plan -out tf.plan
terraform show -json tf.plan | jq > tf.json
checkov -f tf.json
```

## Shipping a new version

1. The development team builds a new AMI from the staging server once the features are in.
2. The new AMI goes into the launch template, which creates a new template version.
3. An instance refresh, from the console or the CLI, replaces instances on a **rolling** strategy with at least 50% healthy at all times.

No downtime, and capacity still tracks demand through target-tracking on average CPU.

## What I'd do next

- **Security:** AWS WAF in front of the load balancer, AWS Shield for DDoS, MFA on every account.
- **Automation:** a CI/CD pipeline for deployments, and Terraform covering every component.
- **Observability:** centralized logs and request tracing with AWS X-Ray.
- **Cost:** reserved capacity for the baseline and regular right-sizing reviews.
